## 5. Implikationen für die Technik (#3745)

1. **Content Collections:** `kapitel` (MDX-Seiten), `quellen`, `foerderprogramme`, `glossar`, `downloads`, `praxisbeispiele`. Alles außer den Seiten als YAML/JSON mit Zod-Schema. Das gibt Sine eine sichere, validierte Struktur.
2. **Navigation:** hybrid. Linear zum Lesen (Kapitel 0→3 mit Vor/Zurück), dazu Nachschlagen über eine Seitennavigation, Zielgruppen-Einstiege („Ich bin … Kommune / WBG“) und eine Volltextsuche (lokal, z. B. Pagefind, keine externen Requests).
3. **PDF (Pflicht laut MS 3):** Die Gesamtfassung wird aus denselben Inhalten erzeugt (Print-Route mit allen Kapiteln + Print-CSS, Build via Playwright/Paged.js). Jede Komponente braucht eine Print-Darstellung, die Karte also ein `fallbackImage`. Fußnoten müssen im PDF als Endnoten erscheinen.
4. **Karte statt Flächen-Finder-Embed (entschieden):** Eine eigene Kartenkomponente (MapLibre) lädt Vektor-Tiles der Beispielflächen von Martin (tilda-geo) und übernimmt die Stile aus dem tilda-geo-Flächenfinder. Was das für die Technik bedeutet:
   - **Datenschutz (#3744):** Die Tiles kommen von einer fremden Domain. Das widerspricht „keine externen Requests“. Möglich sind eine Zwei-Klick-Lösung oder ein statischer Export der Beispielflächen ins Repo (GeoJSON/PMTiles), dann gibt es keinen Laufzeit-Request. Die Hintergrundkarte (Basemap) braucht dieselbe Prüfung.
   - **Betrieb nach Projektende:** Live-Tiles setzen voraus, dass Martin/tilda-geo dauerhaft läuft. Ein statischer Export ist robuster.
   - **Stile:** Kopieren (driftet auseinander) oder aus tilda-geo als Paket bzw. JSON übernehmen?
   - **PDF:** Die Karte erscheint als statisches Bild (`fallbackImage`).
5. **Downloads:** Vorlagen als **.docx** (editierbar) **und PDF**, versioniert im Repo unter `public/downloads/`, mit Metadaten in `downloads`. Die Kanzlei-Freigabe wird als Feld (`reviewedBy`) dokumentiert.
6. **Quellen:** zentral in `quellen` mit IDs. Im Text als `<Cite id="..."/>`, automatisch nummeriert, mit Quellenliste pro Seite und gesamt. Keine Freitext-Links für Belege.
7. **Status-Workflow:** Das Frontmatter-Feld `status` und ein Banner auf Seiten im Entwurf (Preview-Deploys) helfen bei Lektorat und Freigaben (#3749).
8. **AGENTS.md für Sine:** Folgendes muss dort geregelt sein:
   - wo Inhalte liegen (`src/content/…`) und was tabu ist (Komponenten, Layout, Config)
   - Komponenten-Katalog mit Beispielen
   - Quellenpflicht (jede Zahl/Rechtsaussage braucht `Cite`)
   - Rechtstexte nur nach Kanzlei-Freigabe ändern
   - Duzen oder Siezen, gendern mit Doppelpunkt (Mieter:innen, wie im Antrag)
   - Bilder und Alt-Texte
   - Ablauf: Branch → Preview → Review
   - `bun run check` vor dem Commit
9. **Open Source / Lizenz:** Laut Antrag werden alle technischen Ergebnisse Open Source. Repo öffentlich machen, Code-Lizenz und Content-Lizenz (z. B. CC BY 4.0) festlegen *(Interpretation: CC BY ist ein Vorschlag)*.
